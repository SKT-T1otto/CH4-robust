# v1→v2参数可辨识性与代码迁移审查

本节是后续研发设计，尚未修改算法或验收收益。以下维数、边界、窗口和噪声设置均为候选开发设置，须先在开发集校准，不代表实物标定或统计保证。

## 1. 收敛到可解释的主问题

v1每车9维、联合30维；v2主实验拟用每车6维：共享水平场幅度g，以及个体阻力d、有效能力e、净垂向偏置b、迟滞系数λ、整数延迟δ。联合参数为1+4×5=21维。

| 分量 | 候选主域 | 选择依据 |
|---|---|---|
| g | [0.15,0.28]，名义0.18 | 同一空间流场的幅度共享，不要求不同位置流速相同 |
| d / e | [0.85,1.2] / [0.85,1.1] | 保留阻力与能力，但需检查轨迹激励能否区分 |
| b | [-0.02,0.025]，名义0 | 相对原名义浮力项的净垂向增量 |
| λ / δ | [0,0.25] / {0,1,2} | 分别描述一阶执行器记忆及整数物理步延迟 |

主域固定flow_z_gain=0、v_max_scale=1。action_noise_std固定已知0或0.01，形成两套分别训练、评估的协议；同一协议内所有方法保持一致。旧flow_z_gain与浮力共同变化的域只作v1压力诊断，不混入v2主排名。

原因来自实际方程：dynamics.py:21、113仅依赖flow_z_gain与buoyancy_bias_delta之和，无法仅凭运动数据分别唯一恢复；改名为净偏置不能宣称解决了原两变量的分离辨识。predict_velocity在9–27行不使用噪声尺度，旧固定残差阈值没有噪声参数条件辨识机制。runtime.py:110–115排除潜在限速样本，也削弱限速参数的识别证据。删除这些推断维度可以减少无依据收缩，不能保证剩余参数必然可辨识；仍应报告可行集合、预测误差与控制价值。

## 3. 输入与Critic候选

保留原43D公共base，尤其reference仍位于39:42。新增6中心+6宽度、valid/support/age、三项延迟支持mask，共18D，前部合计61D。再接H=8的合法转移，每帧位置3、速度3、已发命令3、下一速度3、eligible1，共104D，得到165D；新旧61D语义不同，必须使用不同schema。历史只含截至t−1已结束的转移，不读取t步结果；补帧与有效性应明确区分。

Critic候选为4×165+12动作+33context=705D。33D拟含21D物理量与四车各3D的前动作滤波状态。事实监督在训练隔离路径使用真实z(t−1)；风险查询必须用合法历史在候选参数下推断的z，不能复用真实隐藏状态。公知已发命令队列由历史重构。

该扩展减轻执行器记忆混叠，但不是充分Markov性证明。有限窗口、未知窗口初态、未知地图与任务部分可观测性仍在；需保留候选初态集合或暖机不确定性。下一事实context应使用下一动作前实际状态，不能把z(t−1)、z(t)或突变前后参数错配。

## 4. 必须新增的机制证据

先检查参数映射和名义成对转移/RNG一致；核对0/1/2步延迟脉冲、迟滞递推及复位；构造旧垂向不可辨识等价对，验证新方案只声称净偏置；确认噪声固定而非伪估计；打乱未来字段不得影响当前Actor/估计；核对同一公共g、每车个体候选和候选z的一致采样；验证事实/候选状态无泄漏、Bellman时点、尾部方向及支持回退；最后测试v1检查点拒绝、v2回合边界恢复一致。

以上检查通过仅说明机制可执行。参数覆盖、收益、收敛和相对SIRSA的创新结论仍需独立重训与预先冻结的正式实验。
